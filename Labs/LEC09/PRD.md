# 소닉 애니메이션 뷰어 PRD

## 1. 목적과 개발 범위

`PRE-PRD.md`를 바탕으로, 소닉 스프라이트 시트의 모든 동작을 확대하여 자동 재생하는 뷰어를 개발한다. 사용자는 실행만으로 전체 동작을 반복해서 관찰할 수 있어야 한다.

Python과 pico2d를 사용하며, 실행 코드와 애니메이션 데이터는 하나의 소스 파일에 작성한다. 게임 플레이, 스프라이트 편집, 수동 재생 컨트롤, 사운드는 이번 개발 범위에서 제외한다.

| 산출물 | 경로 및 역할 |
| --- | --- |
| 실행 소스 | `Labs/LEC09/sonic_animation_viewer.py` — 실행 로직과 동작 데이터 |
| 원본 이미지 | `Labs/LEC09/sonic-sprite.png` — 기존 파일 사용 |
| 개발 명세 | `Labs/LEC09/PRD.md` — 요구사항과 완료 기준 |

원본에 적힌 소스 파일명은 `sonic_animation_viewer.py`로 정규화한다. 이미지 이름은 실제 폴더의 파일명을 따른다. 원본 요구 문서와 이미지는 보존한다.

## 2. 필수 요구사항

| ID | 요구사항 | 완료 조건 |
| --- | --- | --- |
| R1 | pico2d 기반 단일 소스 | 별도 Python 모듈이나 외부 동작 설정 파일 없이 실행된다. |
| R2 | 시트의 모든 애니메이션 재생 | 원본에서 식별한 모든 동작이 재생 목록에 포함된다. |
| R3 | 동작별 5회 반복 | 각 동작을 처음부터 끝까지 정확히 5회 재생한다. |
| R4 | 동작 사이 1초 대기 | 5회 완료 후 1초가 지나면 다음 동작을 시작한다. |
| R5 | 전체 목록 무한 순환 | 마지막 동작도 대기한 뒤 첫 동작으로 돌아간다. |
| R6 | 충분한 확대 표시 | 비율을 유지하며 동작을 쉽게 구분할 수 있고 화면 밖으로 잘리지 않는다. |
| R7 | 단계별 개발 | 최소 20개의 의미 있는 개발 커밋을 남긴다. |
| R8 | 화면 크기 1200×800 | 그리기 영역을 가로 1200, 세로 800픽셀로 생성한다. |
| R9 | 이동 동작의 위치 변화 | 걷기·달리기·구르기 등은 재생 시간에 따라 화면에서도 이동한다. |

R1–R7은 원본 요구사항이며, R8과 R9는 추가로 확정한 화면 규격과 이동 표현이다. 마지막 프레임 유지, ESC 종료, 데이터 검증은 구현 기준으로 적용한다. 확대 배율은 기존 8배의 절반인 4배로 적용하고, fps는 동작별 설정을 따른다.

## 3. 사용자 흐름과 화면 구성

1. 프로그램 실행 시 창을 생성하고 이미지를 불러온다.
2. 첫 번째 동작의 첫 프레임부터 자동 재생한다.
3. 같은 동작을 5회 반복한다.
4. 마지막 프레임을 유지한 채 1초간 대기한다.
5. 다음 동작의 첫 프레임부터 같은 규칙으로 재생한다.
6. 마지막 동작까지 끝나면 첫 동작으로 돌아가 계속 반복한다.
7. ESC 또는 창 닫기를 받으면 종료한다.

### 화면 규격

| 항목 | 적용 기준 |
| --- | --- |
| 그리기 영역 | 1200×800픽셀. 운영체제의 창 테두리와 제목 표시줄은 제외한다. |
| 화면 중심 | 동작 시작 시 (600, 400) 부근에 배치하고, 이동 동작은 재생 중 가로 위치를 갱신한다. |
| 배경 | 캐릭터와 구분되는 단색을 사용한다. |
| 확대 | 가로·세로 비율을 유지하고 전체 동작에 공통 4배 확대를 적용한다. |
| 정렬 | 프레임별 기준점을 사용해 여백과 크기 차이에 의한 흔들림을 방지한다. |
| 대기 화면 | 직전 동작의 마지막 프레임을 유지한다. |

매 프레임 화면을 지우고 다시 그려 잔상을 방지한다. 별도 버튼이나 설정 화면은 만들지 않는다. 동작에 포함된 점프나 자세 변화는 보존하며, 가장 큰 동작과 기준점 이동까지 고려해 1200×800 영역의 여백 안에 들어오도록 배율을 정한다.

## 4. 스프라이트 분석과 데이터 명세

### 분석 작업

구현 전에 이미지를 직접 확인하여 전체 동작 목록을 작성한다. 한 행이 한 동작이거나 모든 프레임 크기가 같다고 가정하지 않는다. 텍스트, 테두리, 장식은 재생 대상에서 제외한다.

동작 순서는 시트의 위에서 아래, 같은 구역에서는 왼쪽에서 오른쪽을 기본으로 한다. 시트에서 별도 순서를 제시하면 그 순서를 따른다. 구분이 모호한 영역은 분석 단계에서 확인하고 판단 근거를 기록한다. 현재 문서에서는 확인하지 않은 동작 개수나 좌표를 임의로 확정하지 않는다.

### 코드 내 데이터

| 항목 | 의미 |
| --- | --- |
| 동작 이름 | 동작을 구분할 고유 이름 또는 식별 번호 |
| 프레임 목록 | 실제 재생 순서대로 정렬한 프레임 데이터 |
| 프레임 영역 | 원본 이미지의 x, y, width, height |
| 정렬 기준점 | 프레임 내부의 발 또는 몸통 등 배치 기준 위치 |
| fps | 해당 동작의 초당 재생 프레임 수 |
| speed | 화면 픽셀/초 단위 가로 이동 속도. 0은 제자리, 음수는 초기 왼쪽 이동 |

프레임 영역은 실제 크기에 맞게 개별 지정할 수 있어야 한다. 좌표 원점은 하나로 통일하고, 분석 좌표를 pico2d의 그리기 좌표로 변환하는 처리는 한곳에 모은다. 프레임별 기준점을 이용해 화면의 기준 위치에 정렬한다.

실행 전에 다음 조건을 검증한다.

- 동작 목록과 각 동작의 프레임 목록이 비어 있지 않다.
- 프레임의 가로·세로 크기와 fps가 양수다.
- 모든 프레임 영역이 원본 이미지 범위 안에 있다.
- 잘못된 데이터가 있으면 동작 이름과 프레임 번호를 알리고 종료한다.

## 5. 재생 로직

### 반복과 시간의 정의

한 번의 재생은 첫 프레임부터 마지막 프레임까지 각각 정해진 시간 동안 표시하는 것이다. 마지막 프레임에 도달한 순간이 아니라 마지막 프레임의 표시 시간까지 끝난 시점에 완료 횟수를 증가시킨다.

프레임 수가 N개이고 속도가 F fps이면 1회 재생 시간은 N/F초다. 정상 실행에서 한 동작은 `5 × N/F`초간 재생되고 이후 1초 대기한다. 예를 들어 6프레임을 10 fps로 재생하면 3초 재생 후 1초 대기한다. 이 수치는 규칙 설명용 예시다.

단일 프레임 동작도 프레임 표시 시간이 끝날 때마다 1회로 계산한다. 역재생이나 왕복 재생은 프레임 목록에 명시되지 않는 한 추가하지 않는다.

### 관리할 상태

| 상태값 | 역할 |
| --- | --- |
| 현재 동작 인덱스 | 전체 목록 중 재생할 동작 선택 |
| 현재 프레임 인덱스 | 현재 표시할 프레임 선택 |
| 완료한 반복 횟수 | 0에서 시작하여 재생 완료 시 증가 |
| 재생 상태 | PLAYING 또는 WAITING |
| 프레임 누적 시간 | 다음 프레임으로 진행할 시점 계산 |
| 대기 경과 시간 | 1초 대기 완료 여부 판단 |
| 이동 경과 시간 | 재생 중 위치와 경계에서의 방향 전환 계산. 대기 중에는 유지 |
| 실행 여부 | 종료 이벤트 수신 시 루프 종료 |

### 상태 전환

| 현재 상태 | 발생 조건 | 처리 |
| --- | --- | --- |
| PLAYING | 일반 프레임 표시 시간 종료 | 다음 프레임으로 이동 |
| PLAYING | 마지막 프레임 표시 시간 종료 | 완료 횟수 1 증가 |
| PLAYING | 증가한 완료 횟수가 5 미만 | 같은 동작의 첫 프레임부터 반복 |
| PLAYING | 증가한 완료 횟수가 5 | 마지막 프레임을 유지하고 WAITING 진입 |
| WAITING | 대기 시간 1초 미만 | 화면 유지 및 입력 처리 |
| WAITING | 대기 시간 1초 경과 | 다음 동작 선택 후 PLAYING 진입 |
| WAITING | 마지막 동작의 대기 완료 | 첫 동작 선택 후 PLAYING 진입 |

새 동작을 선택할 때 프레임 인덱스, 완료 횟수, 프레임 누적 시간, 대기 시간을 모두 초기화한다. 첫 실행도 같은 초기화 규칙을 적용한다.

실제 경과 시간을 사용하여 프레임을 진행한다. 화면 갱신 횟수에 따라 재생 속도가 달라지지 않도록 한다. 갱신이 늦어지면 누적 시간을 반영하되 이전 동작의 시간이 새 동작으로 잘못 전달되지 않게 한다.

1초 대기는 상태로 처리한다. 이벤트 처리를 멈추는 긴 지연 호출을 사용하지 않으며, 대기 중에도 화면 갱신과 종료 입력 처리를 계속한다.

### 이동 표현

걷기, 달리기, 고속 달리기, 대시, 구르기, 회전 이동에는 동작별 가로 속도를 적용한다. 피격 자세는 처음에 왼쪽으로 밀려나는 이동을 표현한다. 그 외 정지 자세는 제자리에서 재생한다. 속도는 원본 이미지에 포함된 값이 아닌 뷰어 표시용 설정이며 상세값은 README.md에 기록한다.

같은 동작의 5회 반복 동안 이동은 연속으로 유지한다. 캐릭터 전체가 화면 경계 안쪽 24픽셀 여백에 도달하면 진행 방향을 반전하고 이미지를 좌우 반전한다. 순간적으로 반대편으로 이동시키지 않는다. 마지막 프레임과 도착 위치에서 1초 대기하며, 다음 동작은 중앙의 초기 위치와 방향에서 시작한다. 원본 프레임 내부의 상하 움직임은 기존 기준선 정렬로 유지한다.

## 6. 코드 구조와 실행 조건

단일 파일 안에서도 역할을 함수로 구분한다. 함수명은 구현 과정에서 정하되 다음 책임이 서로 섞이지 않도록 한다.

| 구성 | 책임 |
| --- | --- |
| 설정 상수 | `WINDOW_WIDTH = 1200`, `WINDOW_HEIGHT = 800`, 확대 배율, 기본 fps, 반복 횟수 5, 대기 시간 1초 |
| 동작 데이터 | 전체 동작과 프레임 목록 |
| 초기화 | 창 생성, 이미지 로드, 데이터 검증, 초기 상태 설정 |
| 입력 처리 | ESC와 창 닫기 확인 |
| 상태 갱신 | 프레임 진행, 반복 계산, 대기 처리 |
| 동작 전환 | 다음 동작 선택과 상태 초기화 |
| 화면 출력 | 배경 지우기, 프레임 추출, 확대·정렬, 화면 갱신 |
| 종료 처리 | 정상 종료와 오류 발생 시 생성한 자원 정리 |

이미지 경로는 소스 파일 위치를 기준으로 계산한다. 이미지 로드 실패 시 시도한 경로와 원인을 알리고 종료한다. 잘못된 동작을 조용히 건너뛰어 일부 애니메이션만 재생하지 않는다.

Python과 pico2d가 준비된 환경에서 저장소 루트 기준 다음 명령으로 실행한다.

```text
python Labs/LEC09/sonic_animation_viewer.py
```

| 20 | 동작별 재생 속도 조정 | 각 동작 관찰에 적합한 속도 |
| 21 | 전체 배율과 정렬 보정 | 모든 동작이 1200×800 영역 안에 안정적으로 표시 |
| 22 | 실행 안내와 검증 결과 기록 | 실행 방법과 요구 충족 여부 확인 가능 |

각 커밋 메시지는 실제 변경한 기능을 설명한다. 최종 검증에서 문제가 발견되면 별도의 수정 커밋을 추가한다. 이 문서 작성만으로 구현 단계가 완료된 것으로 간주하지 않는다.

## 8. 검증 시나리오

| 항목 | 확인 방법 | 통과 기준 |
| --- | --- | --- |
| 화면 크기 | 창 생성 설정과 실제 그리기 영역 확인 | 가로 1200, 세로 800픽셀 |
| 전체 동작 포함 | 원본과 동작 목록 대조 | 누락 없이 모든 동작 포함 |
| 프레임 정확성 | 모든 동작 육안 확인 | 인접 그림 혼입, 순서 오류, 잘림 없음 |
| 5회 반복 | 반복 경계 관찰 또는 임시 로그 | 정확히 5회 완료 후 대기 |
| 1초 대기 | 상태 전환 시각 확인 | 1초 이전에 전환하지 않고 정상 실행 시 다음 갱신에 전환 |
| 상태 초기화 | 동작 전환 직후 확인 | 첫 프레임, 완료 횟수 0으로 시작 |
| 무한 순환 | 전체 목록 최소 두 바퀴 실행 | 두 번째 순회에도 동일한 규칙 적용 |
| 단일 프레임 | 해당 동작 또는 임시 데이터 사용 | 5회 계산 후 대기·전환 정상 |
| 확대·정렬 | 가장 크고 작은 동작 포함 전체 확인 | 비율 유지, 충분한 크기, 화면 밖 잘림 없음 |
| 이동 | 동작별 위치·경계·반복·대기를 확인 | 속도에 맞는 연속 이동, 경계 방향 반전, 대기 중 정지, 다음 동작 위치 초기화 |
| 종료 반응 | 재생·대기 중 ESC와 창 닫기 각각 확인 | 대기 완료를 기다리지 않고 종료 |
| 실행 경로 | 저장소 루트와 소스 폴더에서 실행 | 동일한 이미지 정상 로드 |
| 오류 처리 | 임시 잘못된 경로·데이터 사용 | 원인 안내 후 자원 정리 및 종료 |
| 개발 이력 | 소스 구성과 Git 이력 확인 | 실행 소스 1개, 개발 커밋 최소 20개 |

검증용 임시 데이터와 로그는 확인 후 복구하거나 기본 비활성화한다. 화면 관련 항목은 실제 실행으로 확인하고, 반복 횟수와 시간은 필요할 경우 상태 로그로 보조 검증한다.

## 9. 구현 결과와 완료 기준

이미지 분석과 실제 실행을 통해 다음 값을 확정했다.

| 항목 | 구현 결과 |
| --- | --- |
| 화면 | 1200×800픽셀 |
| 동작 데이터 | 자세 변화 기준 19개 그룹, 총 76프레임 |
| 좌표 | 원본 왼쪽 위 기준 개별 영역을 기록하고 그리기 시 변환 |
| 정렬 | 동작별 원본 기준선과 화면 발 기준점 (600, 320) 사용 |
| 속도 | 동작별 3~18 fps. 상세 목록은 README.md 참조 |
| 확대 | 전체 프레임 공통 4배. 기존 8배 대비 가로·세로 표시 크기 절반 |
| 이동 | 9개 동작에 속도 적용, 화면 경계에서 방향 반전, 대기 중 위치 유지 |
| 배경 | 원본 알파 투명도를 유지하고 격자 없는 회색 배경 사용 |

5회 반복, 1초 대기, 전체 동작 무한 순환 규칙을 유지했다. 실행 방법과 동작 목록, 실제 두 바퀴 재생 및 전체 프레임 검증 결과는 [README.md](README.md)에 기록했다.

R1–R9를 모두 충족하고 검증 시나리오를 통과하면 개발 완료로 판단한다. 최종 산출물은 단일 실행 소스, 보존된 원본 이미지, 실행·검증 기록, 최소 20개의 단계별 개발 커밋이다.
