# 소닉 애니메이션 뷰어

1200×800 창에서 소닉의 19개 동작 그룹, 총 76프레임을 자동 재생한다. 각 동작을 5회 반복하고 마지막 프레임에서 1초 대기한 뒤 다음 동작으로 넘어간다. 전체 목록을 끝내면 처음부터 반복한다.

## 실행

Python 3.9 이상과 pico2d가 필요하다. 개발·검증에는 Windows의 Python 3.11과 기존 설치된 pico2d를 사용했다. 이미지 분석용 Pillow는 뷰어 실행에 필요하지 않다.

저장소 루트에서 실행한다.

```powershell
py Labs/LEC09/sonic_animation_viewer.py
```

`python` 명령이 등록된 환경에서는 `py` 대신 `python`을 사용해도 된다. `sonic-sprite.png`는 소스 파일과 같은 폴더에 둔다. 이미지 경로는 소스 위치를 기준으로 하므로 다른 작업 폴더에서도 실행할 수 있다.

- 실행하면 자동으로 재생한다.
- ESC 또는 창 닫기로 종료한다. 1초 대기 중에도 바로 반응한다.
- 창 크기, 확대 배율, 동작별 속도는 소스 상단 설정과 데이터에서 확인할 수 있다.

## 스프라이트 분석 결과

원본은 399×525 RGBA 이미지다. 위에서 아래, 왼쪽에서 오른쪽 순서로 자세의 연속성을 기준 삼아 그룹을 나눴다. 이름은 화면에 보이는 자세를 설명하기 위한 것으로 원작 게임의 공식 동작 명칭을 뜻하지 않는다. 제목과 하단 제작자 문구·마스코트는 재생 대상에서 제외했다.

전체 프레임에 공통 8배 확대를 적용한다. 일반적인 40픽셀 높이의 자세는 화면에서 약 320픽셀로 표시된다. 발 기준점은 (600, 240)이며 일반 자세가 화면 중심 부근에 오도록 배치한다. 동작 내부에서는 원본의 공통 기준선을 사용하여 작은 상하 움직임을 보존한다. 투명 영역에는 격자 없는 회색 배경이 보인다.

한 바퀴의 이론적 시간은 약 61.45초이며, 실제 시간은 화면 갱신 간격과 시스템 부하에 따라 조금 늘어날 수 있다. 프레임 진행은 실제 경과 시간을 따르고, 동작 전환 시 남은 시간을 초기화하여 대기나 다음 동작이 건너뛰어지지 않도록 한다.

## 검증 기록

2026-10-05, Windows / Python 3.11 / 설치된 pico2d에서 확인했다.

| 검증 | 결과 |
| --- | --- |
| 실제 렌더러 크기 | 1200×800 확인 |
| 프레임 전수 검사 | 76프레임 렌더링과 화면 경계 검사 통과 |
| 원본 픽셀 포함 여부 | 원본 y=38~468 영역의 불투명 픽셀 누락 0개 |
| 시각 검수 | 첫 줄 인접 프레임 혼입을 수정하고 전체 프레임 재확인 |
| 5회 반복 경계 | 모든 동작에서 마지막 표시 시간까지 계산 후 대기 진입 |
| 단일 프레임 | crouch, curl, ball에도 동일한 반복·대기 규칙 적용 |
| 상태 순환 | 시간값을 주입한 전체 3바퀴 검증 통과 |
| 실제 시간 재생 | 약 124초간 2바퀴, 38번 동작 전환 정상 |
| 실제 대기 시간 | 1.000~1.015초 측정 |
| 종료 이벤트 | 실제 SDL ESC·QUIT 이벤트를 재생/대기 각각에 주입하여 메인 루프 종료 확인 |
| 경로 독립성 | 저장소 루트와 소스 폴더 기준 이미지 로드 통과 |
| 오류 처리 | 빈 목록, 잘못된 영역·속도·시간 거부; 이미지 누락 시 오류 안내·창 정리·종료 코드 1 확인 |

검증 중 임시 Python 도구로 상태 경계 검사와 SDL 렌더러 캡처를 수행했다. 뷰어의 실행 소스는 `sonic_animation_viewer.py` 하나이며, 테스트 도구와 캡처는 실행에 필요하지 않다. 성능에 따른 프레임 생략이 발생할 수 있는 극단적인 시스템 정지는 위 정상 실행 측정 범위에 포함하지 않는다.

## 개발 이력

`feature/lec09-animation-viewer` 브랜치에서 창 생성 → 입력 → 이미지 로드 → 동작 분석 → 프레임 출력 → 확대·정렬 → 시간 기반 재생 → 반복·대기 → 전체 순환 → 검증·보정 순서로 개발했다. 최소 20개 커밋 요구를 충족하며 각 단계에 실제 변경과 확인 결과를 반영했다.
